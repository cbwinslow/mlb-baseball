# Data Sources

All sources below are free or free-tier. No paid feeds without an explicit decision recorded here.

## Phase 1 — core ingestion (build first)

The seven supplementary lists (previously excluded, ADR-012) were confirmed present in real `cwbox -X` output and built (ADR-020) — one generic parser handles all seven since they share the same plural-container/singular-child XML shape. A "discrepancy files" product some sources referenced does not appear to exist on retrosheet.org — checked directly (site structure, download pages, CSV-product notes); the closest real thing found is "Official Daily Totals" (scanned PDF ledgers from Hall of Fame microfilm, used internally by Retrosheet for proofing), which is scanned images, not structured/parseable data, and genuinely outside this pipeline's technical shape — not built. |

Headerless — field layout is fixed and documented at `retrosheet.org/gamelogs/glfields.txt`, hardcoded in `retrosheet_gamelog.py` after verifying against real downloaded data, not just the doc. |
| **Retrosheet reference files** | Ballpark codes, team ID history, player/manager/coach/umpire biographical data, family relations | Free | Static whole-file downloads (`parkcode.txt`, `TEAMABR.TXT`, `biofile.zip`, `biodata.zip`), fully scriptable | Not per-year — bootstrap and update are the same full reload, like the Chadwick register. `TEAMABR.TXT` is headerless; layout confirmed against `retrosheet.org/TeamIDs.htm`. Retrosheet's current published file is dated 2020 and records 2021 as the shared latest season for active franchises; raw preserves that source value, while `core` treats its shared maximum as open-ended for modern linkage. `biodata.zip` is a newer bundle Retrosheet also distributes — compared byte-for-byte against `biofile.zip`: `biofile0.csv`/`relatives.csv` are identical in both (loaded once), but `biodata.zip` adds `managers0.csv`/`umpires0.csv` (new tables) and `teams0.csv`/`coaches0.csv` (different column layout than the existing tables, landed separately rather than merged). |
| **Retrosheet rosters** | One row per player-team-season, 1871–2025 | Free | Whole-file download (`retrosheet.org/rosters.zip`, ~4,100 per-team-season files inside), fully scriptable | Team and season aren't repeated inside each file — parsed from the filename. Does not load the zip's bundled `UMPIRES{year}.txt` files (redundant with `biodata.zip`'s umpire biographical data). |
| **Retrosheet schedules** | Planned schedule, one row per scheduled game, 1877–2026, including postponement reason and makeup date | Free | Whole-file download (`retrosheet.org/schedule/schedule.zip`, one headered CSV per year inside), fully scriptable | |
| **Retrosheet transactions** | Trades, sales, releases, waivers, free agency, DL/IL, draft picks | Free | Whole-file download (`retrosheet.org/transactions/tranDB.zip`) | **Frozen by Retrosheet as of November 26, 2021** — ongoing maintenance moved to Baseball-Reference. `update()` re-runs the same full load (harmless/idempotent) rather than pretending this source stays current; nothing after the freeze date without a future Baseball-Reference or MLB Stats API connector. |
| **Chadwick Bureau Register** | Canonical player ID crosswalk (Retrosheet/MLBAM/Baseball-Reference/FanGraphs IDs) | Free | CSV on GitHub (`chadwickbureau/register`) | Needed to join across every other source — build this early. |
| **Lahman Database** | Season-level batting/pitching/fielding/team/awards/salary/HOF stats, 1871–present | Free | Manual download (see below), CC BY-SA | Good backfill for pre-Statcast eras. Current release isn't scriptable — see the manual step. |
| **MLB Stats API** (`statsapi.mlb.com`) | Full-history schedule (1901–present, incl. live game status), standings (1969–present), rosters (1901–present), transactions (2000–present), play-by-play at play level + box scores + umpire assignments (2026–present — where Retrosheet's own most recent published season stops), win probability (**1950–present** — a much wider range, since it has no Retrosheet equivalent at all), venues (~1,667, full catalog), team configuration history (name/venue/franchise changes per team), player bios (every person_id ever seen in a roster), amateur draft picks (1965–present), append-only live-game snapshots for any game currently in progress, append-only probable-pitcher snapshots (person_id, not just a name — today plus a few days ahead, ADR-047) for still-upcoming games, plus reference/personnel/official-stats data (ADR-020): sports/leagues/divisions/seasons (whole-catalog reference), season player pool, free agents (2010+, genuinely absent before), team coaches/alumni/personnel, MLB-to-minor-league affiliate mapping, per-team attendance (full franchise history in one call each), season-level game-pace stats, official per-player/per-team season stat totals and category leaders, and the awards-type catalog | Free, public, unauthenticated | `statsapi` Python package (`MLB-StatsAPI` on PyPI, `toddrob99/MLB-StatsAPI` — 830+ stars, actively maintained, GPL-3.0) | Full history landed even where Retrosheet already covers the same seasons — a second, independently-sourced copy is a cross-validation asset, and storage is cheap (ADR-015). Transactions/draft are genuine gap-fills, not duplication: `raw.retrosheet_transaction` is frozen as of November 26, 2021, and Retrosheet has no draft product at all. Play-by-play/box-scores/umpires verified play-for-play equivalent to Retrosheet on a real shared game before trusting it (ADR-017) — scoped to 2026+ only, since pulling further back would duplicate Retrosheet at real per-game API cost (confirmed directly: `raw.retrosheet_gameinfo` already has per-game umpire assignments, and Retrosheet's own box-score tables already cover this). Win probability is the one piece of game-level detail pulled much further back (1950+, ADR-019) — its 1950 boundary was confirmed directly (gamePk-based `game_winProbability`/`game_playByPlay` return real data for a 1950 game, 404/empty for 1949 and every year checked back to 1901), not assumed to extend indefinitely. Deliberately excludes pitch-level tracking data (velocity/spin/location) even though MLB's own game feed has it since 2008 — that's Statcast's job, done better (see below and ADR-017). Deliberately excludes `person_stats` (redundant with box scores), `jobs_umpire_games`/`jobs_officialScorers` (wrong-shape endpoints — see ADR-018), `stats_streaks`/`highLow` (confirmed broken/inaccessible), and per-award recipient history (Lahman already has it — see ADR-020). Reference/personnel/official-stats data (everything from ADR-020) is refreshed only via `bootstrap()`, not the 5-minute cron `update()` — that data doesn't change fast enough to justify ~30 teams' worth of extra API calls every 5 minutes. Live/play-by-play freshness requires `mlb ingest mlb_api --mode update` to run repeatedly — see `scripts/mlb_api_update.sh` and ADR-016. Probable pitchers come from `schedule`'s own `hydrate=probablePitcher` param (verified directly against real 2026 data — confirmed distinct from `statsapi.schedule()`'s own convenience wrapper, which already hydrates a bare probable-pitcher *name* into `raw.mlb_schedule` but no person_id and no scratch history) — landed only via `update()`, change-detected against the last known snapshot per (game_pk, side) so a 5-minute poll doesn't write a duplicate row for an unchanged announcement (ADR-048). |
| **Baseball Savant / Statcast** | Pitch-level tracking data — pitch trajectory/velocity/movement 2008+ (PITCHf/x era), full Statcast fidelity (spin rate, exit velocity, launch angle, hit distance, derived xBA/xwOBA/win-expectancy estimates, bat-tracking 2023+) 2015+ | Free | `pybaseball.statcast()` (already a project dependency), date-range batched | High volume (full 2008–present history estimated at several hours) — fetched in weekly chunks, not one day/game at a time (confirmed ~2.6s/day when batched). Confirmed to be a strict superset of MLB Stats API's own pitch-level data (119 columns vs. ~20) — see ADR-017, which is why pitch-level tracking lives only here, not in `mlb_api.py` too. |
| **Baseball Savant leaderboards** (sprint speed, catcher pop time/framing, outfielder jump/catch probability/directional OAA, outs above average, baserunning splits, plus batter/pitcher exit-velo-barrels, expected stats, percentile ranks, pitch arsenal, and pitch spin-direction comparison) | Season-level leaderboards — some using raw inputs (fielder positioning, hang time, throw timing) not present in the pitch-level `statcast()` export at all, others MLB's own pre-computed aggregates over pitch-level data we already have in full (kept anyway as a cross-validation asset, ADR-020) | Free | `pybaseball.statcast_sprint_speed()`/`statcast_catcher_poptime()`/`statcast_batter_exitvelo_barrels()`/etc (2015+ for all — confirmed via direct testing, 0 rows for 2014) | Own connector (`statcast_leaderboard.py`), separate from `statcast.py` since these are season aggregates (one call/season), not date-range-batched pitch data. `statcast_catcher_framing()`'s installed-library URL is confirmed broken (Savant moved the leaderboard page, `csv=true` now silently ignored) — fetched directly from the corrected URL instead (see ADR-018). 18 leaderboards total. |
| **Baseball-Reference season stats** | Season batting/pitching stat lines, 2008–present (a hard limit in pybaseball itself, not a scoping choice — see ADR-018), plus Baseball-Reference's own WAR calculation (`raw.bref_war_batting`/`raw.bref_war_pitching`, full history back to 1871 — ADR-024) | Free | `pybaseball.batting_stats_bref()`/`pitching_stats_bref()`/`bwar_bat()`/`bwar_pitch()` | Confirmed working directly, unlike FanGraphs (see Deferred, below). `team_batting_bref()`/`team_pitching_bref()` confirmed broken in the installed pybaseball version (`IndexError`) — not built; team aggregates are derivable from `core.play`/`core.pitch` instead. WAR isn't available from any other source in this pipeline (Lahman has no WAR column, MLB Stats API doesn't compute it) — `bwar_bat()`/`bwar_pitch()` return the entire history in one call each (no season parameter exists), confirmed with 126,418/57,686 real rows. Also evaluated and NOT built (ADR-024): `top_prospects()` (confirmed broken — a bug in pybaseball itself), `batting_stats_range()`/`pitching_stats_range()` (redundant date-window slices of data already covered at season granularity), `get_splits()` (real data, but per-player-per-year only with no bulk form — same combinatorial-cost reasoning as excluded awards-recipient history). |
| **Polymarket** | Market-implied probabilities for MLB games (daily moneyline + in-game props, 5,543 closed + 154 open games back to 2021) plus every other MLB-tagged market — postseason series props, MLB Draft props, All-Star Game props, and season-long futures (World Series champion, AL/NL MVP, AL/NL Cy Young) | Free | Public Gamma API (`gamma-api.polymarket.com`), no auth needed for read — confirmed directly, every call below returns real data with no API key | `raw.polymarket_event`/`_market`/`_outcome` (ADR-026): 5,926 events / 64,003 markets / 128,006 outcomes after de-duping, confirmed by running the real bootstrap, not estimated. Daily games found via `GET /series` → MLB has `id=3`; every other MLB-tagged market found via `GET /events?tag_slug=mlb` (broader than just season futures — confirmed directly, an earlier assumption that it was only 5 futures events was wrong, an artifact of an unpaginated single-page call). The two queries overlap heavily (~5,554 daily games also carry the "mlb" tag) — de-duplicated by event id before loading. `outcomes`/`outcomePrices`/`clobTokenIds` (JSON-encoded parallel arrays in the raw API response) exploded into one row per outcome rather than kept as opaque JSON. `bootstrap()`/`update()` are the same full reload — the events endpoint has no per-season filter to scope a partial reload against (confirmed: `start_date_min/max`, which works on `/markets`, returns nothing on `/events`). Paginated via `/events/keyset` (cursor-based), not offset/limit — the offset endpoint rejects anything past ~2,000 with a 422 ("use /events/keyset for deeper pagination"), hit for real on the first production bootstrap since this project's MLB event history is bigger than that. **ADR-049 reversed the original intraday-price-history exclusion**: `backfill_history()` lands full per-token price timeseries via the CLOB API's `/prices-history` endpoint into `raw.polymarket_price` (scoped to MLB daily-game-market tokens, ~126K of them, confirmed directly — season-futures/postseason-prop/draft-prop tokens are a follow-up, not built), and every `bootstrap()`/`update()` run also appends a current-price snapshot for still-open markets into `raw.polymarket_snapshot` (append-only, no extra API calls — reuses data the run already fetched). |

## Manual step required: Lahman Database

SABR distributes the current Lahman release only through a Box.com folder with no stable, scriptable download URL (confirmed: Box's API returns 401 without an app-registered OAuth token; anonymous downloads only work through the interactive web UI). This is a real constraint, not a shortcut — to bootstrap or refresh current-season Lahman data:

1. Open the current release folder: <https://sabr.box.com/s/y1prhc795jk8zvmelfd3jq7tl389y6cd> (linked from <https://sabr.org/lahman-database/>).
2. Download the whole folder as a zip (top-right download icon), or download it as directed on the page.
3. Save the zip into `downloads/` at the repo root, e.g. `downloads/lahman_1871-2025_csv.zip`. The connector globs `downloads/lahman*.zip` and picks the most recently modified match, so the exact filename doesn't matter.
4. Run `mlb ingest lahman --mode bootstrap` (or `update`) — it loads directly from the zip, no extraction needed.

If no local zip is present, the connector automatically falls back to a network source frozen at the 2021 season (a preserved fork of the since-deleted `chadwickbureau/baseballdatabank`, see `docs/DECISIONS.md`) and prints a clear warning — so a fresh clone still bootstraps with zero setup, just with stale data until someone does the manual step above.

`downloads/` is gitignored — never commit the zip itself, only the instructions for getting it.

## Phase 1b / stretch — prediction markets (once core pipeline pattern is proven)

Both Polymarket and Kalshi (above, in the main Phase 1 table) are built — see ADR-026/ADR-027. Nothing left in this section.

This pairing is a deliberate differentiator: it gives the project a free proxy for "the market's opinion" without a paid odds feed — comparable in spirit to what oddstrader shows, without oddstrader's licensing costs.

## Deferred — not in scope yet

- **Traditional sportsbook odds APIs** (e.g. The Odds API) — paid beyond a very limited free tier; revisit only if Polymarket/Kalshi coverage proves insufficient for the website.
- **FanGraphs** — confirmed BROKEN, not just ToS-sensitive: `pybaseball.batting_stats()`/`pitching_stats()` reproduced directly in this environment return `HTTPError: Error accessing 'https://www.fangraphs.com/leaders-legacy.aspx'. Received status code 403` — fangraphs.com now sits behind Cloudflare, which blocks pybaseball's scraper outright. Not a rate-limit or occasional-failure issue; every call fails the same way. Baseball-Reference (`bref.py`) covers most of the same season-stats value instead (see above). Revisit only if a maintained pybaseball fork adds a working, non-Cloudflare-blocked path, or FanGraphs publishes an actual API.
