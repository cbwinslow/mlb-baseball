# Roadmap

Only Phase 1 is broken into concrete steps right now — Phases 2 and 3 get planned when Phase 1 is actually done (see [NORTH_STAR.md](NORTH_STAR.md)).

## Phase 1 — Data ingestion pipeline

Rough build order, each step re-runnable and tested before moving to the next:

1. ✅ **Project scaffolding** — repo layout, `.env.example`, dependency management, DB connection helper, migration tooling for the raw/core/gold schemas.
2. ✅ **Chadwick Bureau Register connector** — the ID crosswalk. Built first because every other source gets joined against it.
3. ✅ **Lahman connector** — season-level historical stats. Current data requires a manual download (see `docs/DATA_SOURCES.md`); network fallback frozen at 2021.
4. ✅ **Retrosheet connectors** (eight — see `docs/DATA_SOURCES.md`) — pre-parsed CSV product (`retrosheet`, ADR-004); raw play-by-play event files via `cwevent`/`cwgame`, 1910–2025 plus post-season/all-star/Negro League (`retrosheet_event`, ADR-009/ADR-010); box-score-only games via `cwbox` for everything raw event files don't cover — 1871/1872/1874 NA seasons, 1898–1909, and additional Negro League games (`retrosheet_box`, ADR-012); classic game logs back to 1871 plus postseason logs (`retrosheet_gamelog`); ballpark/team/biographical reference data (`retrosheet_reference`); annual rosters (`retrosheet_roster`); planned schedules (`retrosheet_schedule`); the (frozen) transaction database (`retrosheet_transaction`). Reconciled against the CSV product end to end: 98.3% of all games have raw-file coverage; the remainder is a genuine gap in what Retrosheet has published as a standalone download, not a parsing limitation — see ADR-012.
5. ✅ **Reusable ingestion infrastructure** — disk-persisted downloads with a per-source JSON manifest so a bootstrap is resumable without re-fetching (`mlb_baseball/manifest.py`, ADR-008); `mlb doctor` hardened to report cleanly (not crash) on a database that's never been migrated, plus checks for the `downloads/` directory and the Chadwick CLI tools (ADR-011); `mlb_baseball/load.py`'s loader now tolerates a later batch having columns an earlier one didn't, rather than failing on COPY.
6. ✅ **MLB Stats API connector** (`mlb_api`, ADR-015/016/017/018/019/020/025) — full-history schedule (1901–present), standings (1969–present), rosters (1901–present), transactions (2000–present, fills the real gap left by `retrosheet_transaction`'s Nov 2021 freeze), venues (~1,667, full catalog), team configuration history, player bios, and amateur draft picks (1965–present); play-by-play/box-scores/umpire-assignments from 2026 on (exactly where Retrosheet's own most recent published season stops, verified play-for-play equivalent on a real shared game first); win-probability/linescore/game-context from **1950 on** — a much wider range, since it has no Retrosheet equivalent at all (ADR-019); append-only live-game-state capture (`raw.mlb_live_game`). Extended (ADR-020) with the full reference/personnel/organizational surface: sports/leagues/divisions/seasons, player pool, free agents, coaches, alumni, personnel, affiliates, attendance, game pace, official per-player/per-team season stats and category leaders, awards catalog, conferences, official scorer/umpire/datacaster directories — every one of the API's 64 endpoints is now built, confirmed broken, or explicitly excluded with evidence. Scheduled via cron every 5 minutes (`scripts/mlb_api_update.sh`, ADR-016) for live/schedule/standings freshness; the ADR-020 reference/personnel data deliberately isn't on that cron (refreshed only via an occasional manual `bootstrap()` re-run — re-running it every 5 minutes would be pure API load with no freshness benefit). `net.call_with_retry` no longer wastes the full retry budget on a confirmed 404 (ADR-025) — found while running the full historical backfill, a real fix, not speculative.
7. ✅ **Statcast connector** (`statcast`, ADR-017) — pitch-level tracking data via `pybaseball.statcast()`, full history from 2008 (PITCHf/x era; full Statcast fidelity from 2015). Confirmed a strict superset of MLB API's own pitch data (119 columns vs. ~20), so all pitch-level tracking lives here exclusively. Weekly date-range batching, ~2.6s/day confirmed. Full 2008–present history bootstrapped against production (13.4M+ rows), zero known gaps.
8. ✅ **Core layer** — dimensions and facts built on top of the raw tables, joined via the Chadwick crosswalk (`mlb_baseball/conform.py`, `mlb conform`, ADR-013). `core.player`/`core.team`/`core.game` (dimensions, real PK/FK/indices) and `core.play`/`core.pitch` (facts, unifying Retrosheet+MLB API plays and Statcast pitches respectively) all built and verified against production. Extended (ADR-028) with `core.market` (Polymarket/Kalshi market-implied probability, matched to `core.game` — this project's own stated differentiator per `NORTH_STAR.md`, previously inert in `raw`), `core.player_war` (Baseball-Reference's own WAR), and win-probability columns on `core.play`. Also fixed a real, separate bug found doing this: `core.team.last_year` was silently NULLing every team match for 2022+ games. Further extended (ADR-029) with `core.team.mlb_team_id` — team identity resolved by MLB's own stable numeric ID, the team equivalent of `core.player.mlbam_id`, self-bootstrapped by majority vote rather than more string matching — plus a small `core.team_alias` table for Polymarket/Kalshi, the one case with no shared numeric ID at all. Fixed the Athletics' 2025 relocation breaking `core.game` team resolution (MLB's schedule data now lists them as bare `"Athletics"`, no city) as part of the same change.
8b. ✅ **Statcast leaderboards + Baseball-Reference connectors** (`statcast_leaderboard`, `bref`, ADR-018/024) — all 18 Savant leaderboards: the original 8 tracking-only ones not derivable from pitch-level data (sprint speed, catcher pop time/framing, outfielder jump/catch-probability/directional-OAA, outs-above-average, baserunning splits), plus 10 official-aggregate leaderboards added per ADR-020's "ingest everything" direction (batter/pitcher exit-velo-barrels, expected stats, percentile ranks, pitch arsenal, arsenal stats, spin-direction comparison). Baseball-Reference season batting/pitching stats plus Baseball-Reference's own WAR calculation (`bwar_bat`/`bwar_pitch`, full history 1871–2026, ADR-024) — not available from Lahman or MLB Stats API. FanGraphs itself confirmed blocked (Cloudflare 403) — not built; see `docs/DATA_SOURCES.md` Deferred section. `pybaseball`'s full exported namespace was checked function-by-function against what's used (ADR-024) — everything not built is either redundant with data already pulled, a confirmed library bug, or genuinely impractical (no bulk form), each with direct evidence, not a guess.
8c. ✅ **Unified bootstrap/update** — `mlb bootstrap`/`mlb update` run every registered connector in one command, iterating `registry.CONNECTORS` (the same list `mlb doctor` uses), logging and continuing past any single connector's failure. Extended with a second, daily cron cadence (`scripts/mlb_daily_update.sh`, ADR-023) covering every connector's `update()`, not just `mlb_api`'s.
8d. ✅ **Retrosheet completeness pass** (`retrosheet_box`, ADR-021) — `cwbox`'s 7 supplementary per-event lists (doubles/triples/homeruns/stolen bases/double plays/triple plays/sac bunts), previously unparsed. "Retrosheet discrepancy files," referenced as a build target from outside this project, confirmed not to exist as an actual Retrosheet product — the closest real match ("Official Daily Totals") turned out to be scanned PDF ledgers, outside this pipeline's technical shape.
8e. ✅ **Pipeline reliability** (ADR-022/023) — stale `meta.ingestion_run` rows (from an externally-killed process) now self-reap via PID liveness checking, run automatically by `mlb doctor`. Bootstrap procedure documented (`docs/ARCHITECTURE.md` "Bootstrap procedure", README "Setup").
9. ✅ **Polymarket connector** (`polymarket`, ADR-026) — MLB daily-game and season-futures market-implied probabilities via the public Gamma API, no auth needed. `outcomes`/`outcomePrices`/`clobTokenIds` exploded into a normalized outcome table. Intraday price history (the CLOB API's `/prices-history`) confirmed working but deliberately not built — no practical bulk form worth the cost yet, same reasoning as ADR-024's `get_splits()` exclusion.
10. ✅ **Kalshi connector** (`kalshi`, ADR-027) — 155 confirmed-MLB series (games, spreads/totals, player props, season leaders, every major award AL/NL, division/league/World Series champions, draft, coaching changes, Home Run Derby, All-Star props). No authentication needed for reads despite the account-signup requirement and documented RSA-PSS request-signing scheme — confirmed directly, that's for trading actions, not public market data.

Phase 1's core ingestion pipeline (steps 2–10) is done: every connector runs cleanly end-to-end, is idempotent, has tests, and (where it has a natural join target) lands in the core layer. Every source's full surface has been explicitly audited against what it actually offers (not assumed complete) — see `docs/DATA_SOURCES.md` and the ADR log in `docs/DECISIONS.md` for the evidence behind every inclusion and exclusion. Nothing left in Phase 1.

## Phase 2 — ML modeling workflows

Kicked off (ADR-032). First target: game win/loss probability. Techniques and sources: [docs/RESEARCH.md](RESEARCH.md); every model decision logged as an ADR (ADR-032/033) same as everything else in this project.

**Built and running against production, end to end:**
- `gold.game_feature` (migrations 0012-0015) — point-in-time win%/last-10 win%/run-diff/Pythagenpat/Elo, one row per game. Sources upcoming games directly from `raw.mlb_schedule` (`core.game` only ever holds completed games by design), identity is `mlb_game_pk` (works before and after a game lands in `core.game`), degrades gracefully if `raw.mlb_schedule` doesn't exist yet.
- Three models in `mlb_baseball/model/`, all writing to `gold.prediction`: **log5** (689 predictions), **Elo** (793 predictions, sequential Python rating walk — not SQL window functions, which don't fit a cross-team-dependent state machine), and **gbm-v1** (XGBoost, ADR-033) — trained on 209K historical games, validated on 4,666 (2024-2025): log-loss 0.6795 vs Elo's 0.6797 (essentially tied) and log5's 0.9295 (log5's season-to-date win% is noisy early in a season and gets punished hard by log-loss — a real limitation of the simplest baseline, not a bug).
- `mlb predict` (daily cron, alongside `mlb conform` — neither was scheduled before this session) generates predictions; `mlb train` (separate, deliberate command, not part of the daily cron) retrains gbm-v1 and only overwrites the saved model if it beats both baselines.

**Honest reading of the gbm-v1 numbers:** barely beating Elo despite having 10 features to Elo's 2 means the current feature set doesn't carry much more signal than Elo's rating already captures. Acted on directly — three more features built and verified against real production data since:

- **Rest days** — trivial, closes a reserved schema gap.
- **Starting-pitcher quality** (true FIP + K%/BB%/HR%, ADR-034) — reconstructed from `raw.retrosheet_event`'s per-play data (season aggregates like `bref_pitching` would leak future starts mid-season, same trap ADR-032 flagged for WAR). Verified against real 2018 deGrom data, then at full scale (13,613 pitcher-seasons) against `raw.bref_pitching`: 98.3% match — matching this project's own already-documented Retrosheet coverage rate almost exactly. Wired as a permanent `mlb doctor` reconciliation, not a one-off check.
- **Park factor** (`mlb_baseball/model/park.py`, ADR-035) — trailing 3-year window, purely derived from `core.game`'s own scores, zero leakage risk by construction, zero external dependency. Verified: Coors Field correctly ranks highest (135.4) in real 2024 data, matching sabermetric consensus.
- **Team wOBA** (`mlb_baseball/model/offense.py`, ADR-036) — FanGraphs' published formula, recreated (not scraped — they explicitly don't support scraping/API access at all). Verified: real 2023 league-average wOBA computed at .317, matching the known value; real 2024 team values all land in the correct .295-.333 range.
- **wRC+** (`mlb_baseball/model/offense.py::compute_wrc_plus`, ADR-037) — park- and league-adjusted extension of team wOBA, built on top of the two features above. Sanity-checked algebraically (league-average hitter in a neutral park must reduce to exactly 100 by definition — a real regression test) and verified: real 2024 values all land in 86.9-103.6, clustered around 100.
- **Prior-season team WAR** (`mlb_baseball/model/war.py`, ADR-038) — closes the last ADR-032-reserved `gold.game_feature` column (`home_war_prior`/`away_war_prior`). Lagged one full season by construction (zero leakage risk), sourced from `core.player_war`. Surfaced a real team-identity crosswalk gap: `core.player_war.team_code` uses Baseball-Reference's own abbreviations, genuinely different from `core.team.retro_team_id`'s Retrosheet codes — fixed with a dedicated `_BREF_TO_RETRO` mapping. Verified: 2023's Braves (55.1 WAR) and Rangers (47.8) — both real, well-known strong teams — correctly rank highest entering 2024.

**gbm-v1 has not yet been retrained against any of these new columns** — that's a real, separate next step, not automatic. **Known gap, shared by starter quality, wOBA, and wRC+**: `raw.retrosheet_event` covers 1910-2025 only, so all three are `NULL` for the live 2026 season `mlb predict` actually serves — needs the equivalent from `raw.mlb_playbyplay`, a separate parsing task. **Also researched**: FanGraphs' UZR/DRS depend on proprietary data with no free path to replicate — a permanent wall, not a "not yet" — but Statcast's Outs Above Average (already ingested, 2016-2026) is a real free substitute worth building later. Remaining backlog: bullpen quality/fatigue, defensive value via OAA — see `docs/RESEARCH.md`. After that: forward-test live against 2026, then market-implied probability as a comparison line once `core.market`'s pre-game-snapshot gap (issue #1) is addressed.
